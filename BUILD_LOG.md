## Chunk 6: plain bisect engine
- `agentbisect/bisect.py`: range resolution (bad = spec/`--bad`/HEAD, good = spec/`--good`; fails with a clear message if missing), `git rev-list --first-parent` history, both ends re-run once ("bad end does not reproduce", "good end is not good"). `narrow(history, results)` is a pure function of saved results (resume-safe); `PlainStrategy` binary-searches, skip/flaky commits count as tried so the nearest untested neighbour is picked (git bisect skip). Unresolvable => status `failed`, exit 4, "culprit is within these skipped/flaky commits: ..." (`metrics.ambiguous`).
- `Strategy` protocol (`next_commit(state)`, `update(state, sha, result)`) is the seam for chunk 7; `run_investigation(store, st, runner=None, strategy=None)`. Each evaluation is begin_step/end_step; `resume_investigation(store, st, runner=None, strategy=None)` returns the CLI exit code (0 ok, 1 error, 4 unresolved).
- After convergence one extra "monotonic probe" evaluates a commit between culprit and bad end; a good result (or any good-after-bad in cached verdicts) adds the warning "multiple regressions likely" and confidence `low`. Confidence: high (clean band, no skips/flaky), medium (inconclusive commits in range), low (non-monotonic). `metrics.confidence_band` holds the good/bad pass rates.
- `BisectState.metrics` (new): strategy, eval_rounds, cost_usd (eval_rounds x `AGENTBISECT_COST_PER_RUN`, default $0.002 estimate), commits_evaluated, cache_hits, warnings. Cache reuse across investigations comes from the runner's VerdictCache (second run on same repo = 0 eval rounds).
- CLI: `investigate ... --strategy plain [--good SHA] [--bad SHA]` runs end to end; `resume ID` calls the engine. Tests: `tests/test_bisect.py` (fake executor over a throwaway 14-commit repo: normal find at every position, skipped neighbours, skipped culprit-adjacent, flaky, crash+resume, non-monotonic, bad end not reproducing, cache reuse, custom strategy, CLI). 53 pass. Not run against the real support-agent-demo or live models.

## Chunk 10a: claude-CLI LLM proxy (subscription backend)
- `agentbisect/llm_proxy.py` + `agentbisect llm-proxy [--port 8787] [--concurrency 3] [--cache]`: stdlib `ThreadingHTTPServer` serving `POST /v1/messages` (non-streaming; stream=true -> 400), `GET /stats`, `GET /health`. Each call shells out to `claude -p --model <exact id> --output-format json --tools "" --system-prompt ... --setting-sources "" --strict-mcp-config --no-session-persistence` in an empty temp cwd. Credentials are never read; only the binary is run.
- Tool use is emulated: schemas + conversation (incl. tool_use/tool_result history) rendered into the prompt, `--json-schema` forces `{text, tool_calls[{name,input}]}`; output validated against the supplied input_schemas (retry once with the error, then 502 Anthropic-style error); blocks get `toolu_*` ids, stop_reason tool_use/end_turn. Tool-free requests (judge) pass the single user message straight through, no schema. tool_choice any/tool enforced, none drops tools. The prompt must say outright that tools are available (first attempt made Haiku claim it had no tools).
- Response `model` and tokens come from the requested model's `modelUsage` entry (the side call to another model is ignored for tokens, included in cost). Rate limits (is_error/api_error_status 429/529 or text match) retry with exponential backoff, then HTTP 429 + `retry-after` so SDK retries behave. Semaphore caps concurrency. Optional cache `.agentbisect/llm_cache` keyed by sha256(model, system, messages, tools, tool_choice).
- LIMITS: temperature cannot be set (logged in /stats `temperatures`, otherwise ignored), so runs are not temperature-0 deterministic. Input tokens include ~1.2k of CLI overhead per call plus the emulated tool prompt (~6k per tool turn with the demo's schemas), so token budgets are inflated but consistent; do not compare against raw API counts. ~3-8 s per call.
- Runner: `RunnerConfig.llm_proxy_url` (default `$AGENTBISECT_LLM_PROXY_URL`) sets `ANTHROPIC_BASE_URL` and dummy `ANTHROPIC_API_KEY=agentbisect-proxy` in the eval env. `investigate --llm-proxy auto|URL|off`: auto starts an in-process proxy (cache on) for the run, prints stats on exit.

## Chunk 10: Fixer (`agentbisect fix <id>`)
- `fixer.py`: a fresh agent (model `FIXER_MODEL`, default claude-sonnet-5-5, via the existing `LLMProxy.messages`, no tools) gets only `culprit.fixer_brief` (culprit diff + original Entire intent + failing evidence) plus the whole current contents of the files the culprit touched (files over 20k chars are not shown and may not be edited); from attempt 2 on also the previous attempts' diffs and failing-check output. It replies with whole-file edits as JSON, applied in a fresh worktree at the investigated HEAD and committed; the checks (`FixChecker`, default `RunnerChecker` = Runner.evaluate_commit on that commit, signature-aware) run on the commit. Up to 3 attempts (`--max-attempts` >= 1), stop at the first pass.
- Isolation: `culprit.PROTECTED` (evidence/, .env*, .git, .agentbisect, secrets files, ground_truth/answer_key/planted names) is stripped from the brief's diff and file context ("N protected files omitted"), `culprit.scrub` drops lines naming answer keys from intent/evidence/failure text, and such paths are refused as edit targets. Tests, eval cases and conftest are also refused as edit targets, as are symlinks and anything resolving outside the worktree. The system prompt says nothing about bisects or planted bugs.
- Best attempt = the passing one, else the last that produced a commit; it becomes branch `agentbisect/fix-<culprit8>`, `<out>/fix-<id>.patch` and `<out>/fix-<id>-pr.md` (rendered by report.py, which now honours `FixAttempt.passed` for Fixer-only attempts). `--open-draft-pr` is the only way to push + `gh pr create --draft` (via `report.open_pr`), and only when the Fixer's checks passed; push/gh errors are recorded in `FixResult.pr_error`, not raised.

## Chunk 11: fix Verifier (`verify.verify_fix`, `agentbisect verify-fix`)
- `verify_fix(st, runner, VerifierInput(repo, commit, branch, base), judge)` -> `VerifyResult` with four `CheckVerdict`s (True / False / None = inconclusive): (1) `target`: the investigation's signature no longer reproduces at the fix, via the same Runner (budget signatures use the median-of-repeats rule against the calibrated baseline); (2) `regression`: every working-suite case that passed at the pre-fix commit (`base`, default the bad end) still passes, signature off so any failure counts; (3) `held_out`: the held-out cases (spec.held_out, else `held_out` rows of `evals/cases.jsonl`: ro3, po4, rw4 in the demo) pass at the good_min rate, so the fix is not overfit; (4) `intent`: `ClaudeIntentJudge` (pinned `JUDGE_MODEL`, default claude-sonnet-5-5; refuses haiku tier; rejects a response that does not echo the pinned model) is shown the culprit's checkpoint intent, the culprit diff and the fix diff and says whether the intent survives (a pure revert fails it). Overall `passed` is True only if all four pass; any False wins; otherwise None. A judge outage, missing intent or missing held-out cases is inconclusive, never a pass.
- `VerifierInput` is a stub dataclass in `verify.py` for the Fixer's `verifier_input` (repo + commit; optional branch/base); swap the import if the Fixer lands one in `models.py`. `record_verification` fills the matching `FixAttempt` (eval_score = regression score, held_out_score, intent_test_passed), stores the result in `metrics.verify_fix[sha]` and moves status to `verifying` when legal.
- CLI: `agentbisect verify-fix ID --commit SHA [--branch B] [--base SHA] [--repo R] [--llm-proxy auto|URL|off]`; exit 0 verified, 1 not verified or error, 2 inconclusive.
