## Chunk 5: intake
- `agentbisect/intake.py`: `TraceSource` ABC with `NeatlogsCliSource` (shells out to `~/.local/neatlogs-cli/bin/neatlogs --host https://app.neatlogs.com --profile neatlogs-us --credential-source profile --json [--project]`; `traces list|get|spans list|payload --fields input`, `detections get|hits|trends`) and `FixtureSource` (recorded JSON, can simulate auth failure). - Real CLI envelope is `{"data": {...}, "success": true}`; list items carry `traceId, workflowName, status, tags, startedAt`; tags are `commit:<sha>`, `case:<id>`, `run:<id>`. Project id needs `--project` or `NEATLOGS_PROJECT_ID`. Trace `input` is only available through span `payload --fields input`.
- `intake_trace`: bad trace -> case (case tag, else exact input match) -> good traces = same case, status not error, commit a strict ancestor of the bad commit (git), newest first, one per commit. Suite = non-held-out cases of that category; `held_out` = every case flagged `held_out` in the target's `evals/cases.jsonl` (an assert guards that the two never overlap; held-out checks are not in the predicate). Predicate = `{order: [checks, budget, rubric], checks per case, budget {max_steps 6, token_factor 1.5}, rubric per case or None}`. `breaks`/`intent_for` are never read.
- `intake_detection` (newest hit trace that maps to a case) and `intake_issue` (`gh issue view --json`, keyword->category match; optional injectable `LLM` interface called with the pinned `JUDGE_MODEL`, fake in tests, no live client shipped).

- Tests: `tests/test_intake.py` (39 total pass). ## Chunk 6: plain bisect engine
- `agentbisect/bisect.py`: range resolution (bad = spec/`--bad`/HEAD, good = spec/`--good`; fails with a clear message if missing), `git rev-list --first-parent` history, both ends re-run once ("bad end does not reproduce", "good end is not good"). `narrow(history, results)` is a pure function of saved results (resume-safe); `PlainStrategy` binary-searches, skip/flaky commits count as tried so the nearest untested neighbour is picked (git bisect skip). Unresolvable => status `failed`, exit 4, "culprit is within these skipped/flaky commits: ..." (`metrics.ambiguous`).
- `Strategy` protocol (`next_commit(state)`, `update(state, sha, result)`) is the seam for chunk 7; `run_investigation(store, st, runner=None, strategy=None)`. Each evaluation is begin_step/end_step; `resume_investigation(store, st, runner=None, strategy=None)` returns the CLI exit code (0 ok, 1 error, 4 unresolved).
- After convergence one extra "monotonic probe" evaluates a commit between culprit and bad end; a good result (or any good-after-bad in cached verdicts) adds the warning "multiple regressions likely" and confidence `low`. Confidence: high (clean band, no skips/flaky), medium (inconclusive commits in range), low (non-monotonic). `metrics.confidence_band` holds the good/bad pass rates.
- `BisectState.metrics` (new): strategy, eval_rounds, cost_usd (eval_rounds x `AGENTBISECT_COST_PER_RUN`, default $0.002 estimate), commits_evaluated, cache_hits, warnings. Cache reuse across investigations comes from the runner's VerdictCache (second run on same repo = 0 eval rounds).
- CLI: `investigate ... --strategy plain [--good SHA] [--bad SHA]` runs end to end; `resume ID` calls the engine. Tests: `tests/test_bisect.py` (fake executor over a throwaway 14-commit repo: normal find at every position, skipped neighbours, skipped culprit-adjacent, flaky, crash+resume, non-monotonic, bad end not reproducing, cache reuse, custom strategy, CLI). 53 pass. Not run against the real support-agent-demo or live models.

## Chunk 7: smart planner
- `agentbisect/planner.py`: `first_divergence` (span diff -> `Plan.divergent_span`), `Planner` (graph impact -> commits touching impacted code -> checkpoint-intent ranking, each candidate `{sha, score, reason}`; score = 0.7 intent match + 0.3 code link), `SmartStrategy` (candidate, then its parent; clean candidate -> re-rank; nothing ranked left -> `PlainStrategy` on the open range, `metrics.planner.fell_back_to_plain`). Decisions are a pure function of the persisted plan + verdicts, so crash/resume re-uses the plan (no re-planning). `compare_strategies` + `agentbisect compare ID` run plain and smart in separate state dirs (empty caches) and print rounds/cost/context tokens.
- Scorers: deterministic `LexicalScorer` (idf-weighted term overlap) by default; `LLMScorer(llm)` takes any `intake.LLM` (no live client ships). No checkpoint -> commit message text (`reason` says `commit_message`).
- `intake.Span` + `TraceSource.spans()` (FixtureSource reads `"spans": {trace_id: [...]}`; `NeatlogsCliSource.spans` lists spans + `payload --fields output` to find chosen tools, real shape UNVERIFIED because the project has no real eval traces yet).
- CLI: `investigate --strategy smart|plain` (default smart, now runs the bisect; `--intake-only` for the old behaviour), `resume` rebuilds the strategy from `metrics.strategy`/`metrics.source`, `compare`.
- Real-tool findings (support-agent-demo, read-only): entire-graph WORKS for Python (`graph capabilities --json` lists Python as semantic). `graph impact --symbol S --repo . --format json --head --exclude-tests`: exact name -> `focus` + `callers.entries[].endpoint.file_path`; ambiguous/fuzzy -> `definitions[]` that include unrelated fuzzy hits (`S`, `one`) and tests, so the adapter keeps only definitions whose qualified name contains the symbol. Impact only sees the committed HEAD tree, not history. `graph commit <sha> --json` -> `files[].changes[{type, kind, name(qualified), dependents_count}]` works. `checkpoint explain <sha> --json` is metadata only (no intent text); intent needs `--full` (`[User]` block `Request:` line; `## Intent` is truncated with `...`; `## Summary` is a placeholder until generated). Commits with no trailer print "has no Entire-Checkpoint trailer" (rc 0); unknown sha rc 1.
- Dry check, real demo repo range 1041d3d..HEAD, hint `search_help`: graph found `ToolBox._tool_search_help` in tools/impl.py; planner read ~3.4KB of graph impact + ~63KB of checkpoint transcripts vs ~216KB estimated for the raw range diff + all intents. Unknown symbol -> graph returns only noise, planner flags `graph_empty`, uses git grep/-S and ranks by intent alone. Weakness: a tool-name hint only finds commits touching the tool file; regressions in loop/prompt code are reached by the plain fallback.
- Tests: `tests/test_planner.py` (fewer rounds than plain on a 30-commit repo, context tokens logged, clean-candidate re-rank, plain fallback, no-checkpoint, graph unavailable, skip, crash/resume, parsers on real output shapes, CLI/compare). 67 pass. No live model or neatlogs call.

## Chunk 8: culprit analyst + revert test
- `agentbisect/culprit.py`: `analyze_culprit` -> `CulpritReport` (checkpoint prompt + reasoning parsed from `entire checkpoint explain --full`, commit-message fallback flagged `no checkpoint`; semantic diff from `entire graph diff --base <sha>~1 --head <sha> --json` + callers via `graph impact`, fallback `git show --stat` + hunk-header symbols; span-by-span good/bad trace divergence; failing evidence). `fixer_brief` = culprit diff + labelled ORIGINAL INTENT + failing evidence only (no log, no other commits). Verified on real support-agent-demo checkpoint/graph output (read-only).
- `agentbisect/verify.py`: `revert_test` builds HEAD-with-culprit-reverted in a fresh worktree (`git revert --no-commit`, snapshotted as a deterministic throwaway commit so Runner/cache/pins are reused and resume is safe), runs the suite cases, passes when the pass rate returns to the good-commit level minus 0.1. Conflicts: abort, retry with only the hunks that still reverse-apply (`git apply -R --reject`); flag `revert conflicts`, confidence down one notch; nothing applicable or unbuildable -> inconclusive (`None`). Revert not fixing -> confidence `low` + `multiple regressions likely` flag/warning. Eval rounds recorded in `metrics.revert_test` and added to `eval_rounds`/cost. Fix-verification hooks left for chunk 11.
- Flow: `investigate`/`resume` run `confirm_culprit` after a bisect culprit (resume-safe, idempotent, status stays `culprit_found`); `status` shows culprit, revert result, rates, intent source, flags. `CulpritReport` gained optional fields (intent_source, trace_divergence, failing_evidence, flags, revert_details, analyzed); `_conclude` keeps an existing analysed culprit on resume.
- Tests: `tests/test_culprit.py` (normal pass, wrong culprit, conflict inconclusive, partial revert, unbuildable, deterministic commit, no-checkpoint, graph diff, trace divergence, Fixer brief isolation, status). 79 pass. No live model/neatlogs call; no UI so no screenshot.
