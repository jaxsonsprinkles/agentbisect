5. `verify.py:~410` (`check_regression`), signature handling for budget signatures. With `runner.signature = None`, `_tally` uses raw per-run `fails`, which includes the harness's per-run `budget:*` flags. The median rule is skipped. For a budget-signature investigation, one token outlier in a previously clean case (for example 1 of 3 runs, rate 0.67 against a base of 1.0) is reported as "regressed". There is also no escalation, because `evaluate_commit` only re-runs disagreeing cases when the overall band is "uncertain", and here it is "good". The inverse also holds. Cases that failed only on per-run budget flags at base are dropped from `passing`, so budget regressions in other cases are never caught. Fix: judge regressions per case with the median rule when the flag is a budget one. Or pass `budget_cases=cases` for budget signatures and use a signature that selects `budget:*`. At minimum, re-run any case that disagrees with itself (rate strictly between 0 and 1) before declaring it regressed.

6. `verify.py:~405`, flaky case on the regression side. `evaluate_commit` escalates repeats only when the overall verdict is uncertain, so a single 2/3 case in an otherwise green suite is never re-run. It is flagged `regressed` because `a[c] &lt; b[c] - 0.1`. Because of the same escalation gate, an already-flaky case at base (for example 0.67) is excluded from `passing`, so a fix that makes it fully fail is never reported. Fix: for any case with `0 &lt; rate &lt; 1` at either commit, re-run with higher repeats. Compare using a count/binomial rule, not a raw 0.1 gap. Also avoid float edge cases such as `0.8 &lt; 0.9 - 0.1`.

7. `verify.py:~480`, `held_out_cases` fallback reads `load_cases(st.repo)` from the working tree, not `vin.repo` or the fix commit. Held-out cases added in the fix commit, or a missing `evals/cases.jsonl` at HEAD, give wrong or inconclusive results. An `IntakeError` also raises out of `verify_fix` after the expensive target and regression runs, and discards them. The CLI catches it (it is a `RuntimeError`), but no result is recorded. Fix: catch `IntakeError` in `held_out_cases` and return `[]`, which makes the check inconclusive.

8. `verify.py:~500` (`record_verification`), duplicate `FixAttempt` entries. A branch-less verification never matches an existing attempt, because the lookup requires `vin.branch`, but the new attempt's branch is the commit SHA. Re-verifying the same commit therefore appends a new attempt each time. Fix: match `a.branch in (vin.branch, res.commit)`.

- **Regression:** cases that passed at the pre-fix commit (default: the investigation's bad end, overridable with `--base`) must still pass.
